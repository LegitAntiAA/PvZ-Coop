# Fusion source data and native asset pipeline

## Day lawn extension (FIELD-ART32)

The Fusion mode's native-style day lawn uses `assets/fusion/fields/classic-day-10.png`, a single opaque1586x992 ten-column/five-row image generated with the built-in `image_gen` edit tool at the user's explicit request. The clean original native1880x720 day background was the reference; house/street/borders still come from that original resource. Only the Fusion-only native lawn rectangle is replaced in one draw, not per-column tiles. The ordinary Classic mode does not use this image.

Output SHA256: `9B34B264383F4C95F169174E91F209DD64AADCF0AD28B0371D833E69C7FE2169`; original reference SHA256: `0D557832979E0FD90000D23EECFEDE80F35CF254BB4AA9B935704FD3333EA9CF`. The exact prompt is stored at `tools/fusion/reference/classic-day-10.prompt.txt`. Standard asset deployment copies the PNG into `bin/fusion/fields`; the native smoke checks that resource and rejects field-load errors.

The Fusion-style source backdrop now translates down by the source-derived12.874px so its grass bottom meets native y580. Its previous stretched bottom strip is gone. Cell positions, hit testing and authoritative entities are unchanged. Native32b actual host800/client1066 full smoke Passed593 common hashes; Root viewed both actual SDL field frames and confirmed the previous pasted-column seam is absent. Images generated by the old offline field-preview script describe the superseded retile implementation.

The local source is Fusion 2.3.1. The source inventory is substantially larger
than the currently implemented native runtime. A catalog entry, exported texture,
compiled renderer, or animation preview does not establish a ported gameplay ability.

## Reproduce the catalog

From the repository root, with Python 3:

```powershell
python tools/fusion/export_catalog.py --source C:/PvZ/fusion/mod
```

The output is `assets/fusion/catalog`. Original paths in its manifest are relative
to the supplied Fusion directory; sprite/prefab paths are relative to
`ExportedProject/Assets`. No absolute developer-machine paths are compiled into
the catalog. Original input files have SHA-256 provenance.

| Original source | Content |
| --- | --- |
| `analysis/game_enums.json` | 287 PlantType enum values, 95 ZombieType values, 100 BulletType values |
| `Resources/plant_data.txt` | 283 rows of base plant statistics; GB18030 CSV, not JSON |
| `Resources/LawnStrings.json` | 281 source plant almanac entries, including original rich text |
| `Resources/ZombieStrings.json` | 88 source zombie almanac entries |
| `tools/fusion/reference/zombie-stats-2.3.1.json` | 94 base zombie records transcribed from 188 packed native stores, with method VAs and binary hash |

Plant IDs are sparse and reach 1192. Zombie IDs reach 224. Never reinterpret these
IDs as Classic `SeedType` or `ZombieType` ordinals. `LawnFusion::FusionPlantId` is
uint16_t; the native no-plant sentinel is 65535, whereas the source enum has -1.
Native catalog iteration excludes the negative sentinel and contains 286 plants,
94 zombies, and 100 bullets. Unknown lookups return nullptr.

The source plant enum IDs without CSV statistics are -1/Nothing, 257/Pit,
258/Refrash, and 800/CustomPeashooter. Their statistics stay absent. Source cost
-100 for PresentZombie is retained rather than silently clamped. Catalog membership
does not establish card eligibility, an unlock rule, or ability support; unverified
eligibility/unlock fields are null and runtimeImplemented is false in this inventory.

`FusionCatalog.{h,cpp}` exposes the generated base plant stats and entity names,
plus `FusionFindZombieStats`. The almanac JSON retains complete source strings.
The generator validates duplicate enum IDs/names, unknown stat/almanac IDs,
numeric fields, referenced asset existence, and script GUIDs in candidate prefabs.
An existing analysis map labelled "exact" is not by itself proof that a prefab is
the gameplay prefab. `scriptGuidVerifiedPrefabs` records the independent script check.

## Original statistics and overrides

Ghidra `PlantDataLoader.LoadPlantData` (VA 0x1803B87E0) directly reads the CSV's
seven numeric columns into plantData[plantID]. `CreatePlant.SetPlant`
(0x18044C950) copies damage, attack/production intervals and HP, then invokes
virtual InitPlant. Per-class InitPlant overrides therefore remain authoritative
after base CSV data. SetPlantAttributes also randomizes speed and initial timers;
the catalog alone cannot reproduce those behaviors.

Zombie base records are initialized by InitZombieData (0x1803BA5C0), PlantZombie
(0x1803BB0E0), and TravelZombie (0x1803BB590), in disjoint groups of 49, 20, and 25.
TravelZombie runs unconditionally during table construction. Its records are not
conditional travel-health multipliers. CreateZombie.GetZombieData (0x18044FB00)
applies board/map/travel health factors after copying the four base integers.

## Animation conversion

```powershell
python tools/fusion/export_animation.py --assets C:/PvZ/fusion/mod/assetripper/extracted/AssetRipper_export_20261112_215914/ExportedProject/Assets --prefab Resources/plants/peashooter/PeashooterPrefab.prefab --output assets/fusion/pilot/peashooter
```

The exporter requires Python 3. `rg`, when available, accelerates resolution of
external GUIDs; otherwise it uses a slower Python metadata scan. It executes no
game code. It keeps original PNG atlas bytes, Transform hierarchy, SpriteRenderer
order/activity/color/flips, sprite rect/pivot/pixels-per-unit, Hermite keys/slopes,
clip events, controller speeds/layers, and raw source sprite/controller metadata.
Box collider geometry is also exported. Large Unity fileIDs are parsed as integers,
never through floating point. Animation binding paths are relative to the Animator
object and are resolved to the package hierarchy.

Prepared pilot profiles:

| --- | --- | --- |
| peashooter, ID 0 | plants/peashooter/PeashooterPrefab | 15 / 14 / 1 |
| sunflower, ID 1 | plants/sunflower/SunflowerPrefab | 13 / 11 / 2 |
| peasunflower, ID 1000 | plants/_mixer/peasunflower/PeaSunFlowerPrefab | 21 / 20 / 4 |

The artist-only `plants/peashooter/PeaShooter.prefab` and
`zombies/zombie/Zombie.prefab` are not the corresponding gameplay prefabs.
PeaSunFlower has one source animation binding to a missing artist node
PeaShooter_sprout; Unity ignores that binding, and the package records it explicitly.

`FusionAnimation` loads this package, owns SharedImageRef texture lifetimes, and
draws supplied authoritative phases. Draw x/y replace the prefab's editor root
position. The caller supplies scale after a 100-pixels-per-Unity-unit baseline.
`DrawPose` selects named base/action states. An additive shoot layer uses the
first-frame reference; in the current shooter pilots the position/scale reference
values match the prefab rest values. General additive-reference/avatar behavior
still requires separate verification. Rendering never dispatches gameplay events.

Peashooter/DoubleShooter/Gatling idle speed is 1.3; SunFlower/PeaSunFlower idle
speed is 1. BasicZombie idle speed is 0.7, walk 0.4, walk2 0.5. Original event time
must be divided by state speed and active Animator Speed before scheduling it.
BasicZombie walk root-position keys and collider/shadow offsets remain in the
source package. Source Animator root motion plus Zombie.PositionUpdate's explicit
deltaPosition application needs a source-runtime comparison; do not infer an
average movement rate or claim the apparent double application is proven.

Weighted curves, 3D quaternion animation, unrelated float/object bindings, and
actual SpriteSkin deformation are not silently approximated by the converter.
Source particle systems are retained as deferred components and are not rendered
by this pilot. Native drawing now uses source mesh positions and triangle indices.
Nonzero source UVs are retained; AssetRipper's zero-filled UV streams are recovered
from serialized uvTransform. That interpretation and material/filter equivalence
still require source-runtime visual comparison. Fractional source sprite rectangles
do not round the actual mesh. Active skin deformation remains separate work.

## Native presentation adapter

`FusionPresentation.Load(app, "assets/fusion/pilot", error)` loads the supported
world profiles and actual source Preview portraits. `Draw(graphics, state, width,
height, cosmeticElapsed)` renders the supplied snapshot without running gameplay
or animation events. `GetFusionViewport` provides the same projection for input:
1066x600 uses the full viewport at60 pixels/source unit; 800x600 uses800x450 with
top75 at45 pixels/unit. UnprojectScreen rejects letterbox input.

Simulation actor positions are ground/Shadow anchors. The exporter computes each
Shadow offset from the original Transform chain, excluding editor root translation.
Presentation subtracts this offset once. Simulation animationTime/shootAnimationTime
already contain controller/actor speed; presentation divides by state speed and
renders with Animator Speed=1, avoiding double speed.

Visual profiles now include SplitPea1090. It has one additive Shoot layer, not two
independent layers: speed2*Speed, duration1.3333334, AnimShoot at0.6666667 and
AnimShoot2 at1.0. Source Preview packages exist for0/1/1000/1030/1032/1090.
DrawPlantPortrait fits their mesh bounds into a native seed-packet frame. Runtime
owns frame, price, EXTRA marker and interactions.

GameAPP.LoadBullet resolves projectile0 to Bullet/Prefabs/ProjectilePea and8 to
Bullet/Prefabs/BulletSun. LoadItem resolves item0 to Items/Sun/Sun and13 to
Items/Sun/BulletSun. Static sprites use explicit static packages rather than
invented Animator states. Cosmetic item creation phase is not inferred when the
snapshot lacks an original creation/animation timer.

Zombie loss appearance follows verified source helpers: FindAndDestoryZombieHand
0x180383F90 destroys tag ZombieHand; FindAndDestoryZombieHead0x180384210 destroys
ZombieHead/ZombieJaw; FindAndReplaceArmUpperSprite0x1803844C0 finds ZombieArmUpper;
ChangeArmSpirte0x180380B60 substitutes spritePrefab[0] with scale(4,4,4). That sprite
is Zombies/Image/reanim/Zombie_outerarm_upper2, loaded by GameAPP.LoadSprite.
DrawOptions apply the source tags/replacement. Detached head/arm particles remain
unimplemented. TagManager and source SetLayer establish per-row plant→zombie→bullet
ordering, with coins above rows. Descending plant-column order matches source
sortingOrder=(100-column)*100+stackCount.

## Day background and source framing

`pilot/background1` contains the original bg visual subtree of background1.prefab,
with 9 nodes, 7 SpriteRenderers and 2 PNG files. Its full original hierarchy and
deferred SpriteMask metadata remain in the package; ice-road gameplay rendering
is not included in this initial-day visual package. Source MonoBehaviour GUIDs
resolve to GiveFertilize, GameLose, FloorMgr and IceRoad, with no SpriteSkin.
PSD bone metadata on two sprites is preserved verbatim and explicitly allowed by
the converter option; that does not claim support for active skeletal deformation.

```powershell
python tools/fusion/export_animation.py --assets C:/PvZ/fusion/mod/assetripper/extracted/AssetRipper_export_20261112_215914/ExportedProject/Assets --prefab Resources/background/background1.prefab --output assets/fusion/pilot/background1 --active-only --sprite-prefix bg --allow-unused-sprite-bones
```

Source background root is (-10,5), child bg is (12,-10) at scale 1.7. Use that source
root world position as the Draw anchor; the renderer does not add the editor root
translation again. Hold the background at phase 0 for the initial-day pose; the
GiveFertilize animation/event is a separate gameplay interaction.

The source scene main camera is orthographic size 5 with full viewport; UI reference
resolution is 1920x1080, height matched. InitBoard sets camera x=-1 initially, moves
to preview x=5 for ten columns, then returns gameplay x=0, retaining y=0,z=-200.
The source first-campaign grid is five rows and ten columns; its cell centers are
x=1.35*column-4.8, y=2.3-1.67*row. Native projection should preserve this world frame
and fit it into the game viewport rather than substitute the Classic nine-column lawn.

# Native rotation correction (FUSION-RENDER-FIX01)

The first native load reached two original nonplanar particle-marker rotations in
Zombie (`LoseHead`/`LoseArm`, X=-90 degrees). Its `die` clip also has a visible
`Zombie_outerleg_lower` Euler tilt (X=-0.783, Y=-0.142 degrees), so ignoring helper
rotations alone would not make the complete source package load correctly.
The native renderer now composes full 3D local TRS matrices and projects sprite
XY vertices orthographically only after hierarchy composition. Original
quaternions, ZXY Euler curves, negative scale/reflection and child Z offsets are
retained. This does not add particle rendering or skeletal deformation.

`CreateZombie.SetTransform` at `0x18044FF30` was checked in Ghidra: it offsets the
root position by its Shadow position and reparents it; it does not reset local
child rotations. The source-only check compared all 900 exported Euler keys
against independent sequential Z/X/Y rotations, including a Y180 reflection.
It passed; native load and visual acceptance still require Root's next build.
