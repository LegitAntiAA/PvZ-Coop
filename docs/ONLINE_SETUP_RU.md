# Онлайн-комнаты без VPN: настройка Cloudflare и WebRTC

Игра использует ваш Cloudflare Worker для списка комнат и обмена SDP/ICE.
Игровые данные идут напрямую между игроками через надёжный упорядоченный
WebRTC DataChannel, зашифрованный DTLS. Платный сервер и TURN не используются.

Cloudflare разрешает SQLite Durable Objects на Workers Free. Бесплатный тариф
имеет квоты; при их превышении операции останавливаются до сброса лимита.
Для этого проекта выбирайте Free, без подключения платного тарифа.
Актуальные условия: [официальная тарификация Durable Objects](https://developers.cloudflare.com/durable-objects/platform/pricing/).

## 1. Подготовить игровой клиент

Для обычных игроков достаточно одинакового готового архива мода, содержащего
`PlantsVsZombies.exe`, `datachannel.dll`, необходимые ресурсы и уведомления о
лицензиях. Отдельный сервер для каждого игрока не нужен.

Для самостоятельной сборки нужны Git, CMake и Visual Studio C++ Build Tools.
В PowerShell из корня репозитория выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\BuildOnlineDeps.ps1 -Platform Win32
```

Скрипт получает точные ревизии libdatachannel 0.24.5, Mbed TLS 3.6.7 и их
зависимостей в `work/vendor`, собирает DLL и кладёт её в `lib/online/Win32`.
При уже существующей изменённой ревизии скрипт завершается с объяснением,
сохраняя локальные файлы. Он не меняет системные пути DLL или настройки защиты.

Затем соберите `PlantsVsZombies.sln`, `ReleaseGOTY`, `Win32`. Рядом с итоговым EXE
должна находиться DLL той же архитектуры. Для x64 сначала запустите скрипт
с `-Platform x64` и соберите игру для x64. LAN и одиночная игра могут работать
без необязательной DLL; онлайн-браузер при её отсутствии объяснит, чего не хватает.

Одна сборка получает собственный идентификатор. Раздавайте всем игрокам один
и тот же готовый архив: даже одинаковый исходный код, собранный повторно, может
получить другой номер. В браузере видны только комнаты точно такой же сборки;
прямое подключение с другим идентификатором также отклоняется.

## 2. Создать бесплатный Cloudflare Worker

Эту настройку делает один организатор. Остальные используют полученный URL.

1. Откройте [Cloudflare Dashboard](https://dash.cloudflare.com/) и войдите или
   создайте аккаунт. В разделе Workers & Pages выберите бесплатный Workers Free.
   Собственный домен не требуется: подходит адрес `workers.dev`.
2. Установите Node.js, совместимый с закреплённым Wrangler. Проверенный локально
   комплект использует Node.js 24.16.0 и Wrangler 4.160.1.
3. Откройте PowerShell в `online/signaling` внутри репозитория и выполните:

   ```powershell
   npm.cmd ci
   npx.cmd wrangler login
   ```

4. Wrangler откроет браузер для входа. Пройдите вход самостоятельно и разрешите
   доступ к нужному Cloudflare аккаунту. API-токен не нужно вставлять в чат,
   игру, `coop.ini` или репозиторий.
5. Проверьте `wrangler.jsonc`. Поле `name` задаёт имя Worker. Можно оставить
   `pvz-coop-signaling` или выбрать свободное имя. Не удаляйте привязку
   `DIRECTORY`, класс `RoomDirectory` и миграцию `new_sqlite_classes`: именно
   SQLite-вариант подходит для Free.
6. Опубликуйте Worker:

   ```powershell
   npm.cmd run deploy
   ```

7. Скопируйте HTTPS-адрес, выведенный Wrangler, например
   `https://pvz-coop-signaling.your-subdomain.workers.dev`.
8. Откройте этот адрес с `/health` в конце. Ожидается JSON с
   `service: "pvz-coop-signaling"` и `schema: 1`.

Публикацию и вход выполняет владелец аккаунта. В этой рабочей сессии Worker
проверялся локально и не публиковался в чужой Cloudflare аккаунт.
Дополнительная документация: [команды Wrangler](https://developers.cloudflare.com/workers/wrangler/commands/),
[WebSocket Hibernation](https://developers.cloudflare.com/durable-objects/best-practices/websockets/).

## 3. Указать URL в игре

В окне онлайн-комнат введите адрес своего Worker и нажмите подключение.
Можно также сохранить его в `coop.ini` рядом с EXE:

```ini
online_endpoint=https://pvz-coop-signaling.your-subdomain.workers.dev
stun_server=stun:stun.cloudflare.com:3478
```

`/signal` добавляется автоматически, если указан корневой адрес Worker.
Раздайте всем участникам одинаковый URL и одинаковую сборку игры.

Хост указывает название, необязательный пароль и число участников от 2 до 4,
включая хоста, затем создаёт комнату. Клиент выбирает комнату и вводит пароль,
если она защищена. Комнаты с активной игрой помечены соответствующим состоянием;
возможности позднего подключения определяются игровым клиентом.

Пароль не передаётся в URL и не отображается в списке комнат. Клиент вычисляет
PBKDF2-SHA256 с уникальной случайной солью и 100 000 итераций. Worker хранит
проверочное значение в состоянии комнаты, сравнивает его без раннего выхода
по совпадающему префиксу и ограничивает повторные неверные попытки в сессии.

Чтобы обновить службу после изменения исходников Worker, повторите
`npm.cmd ci` и `npm.cmd run deploy` из той же папки и аккаунта. Игровые
снапшоты через Worker не проходят.

## 4. Ограничения прямого подключения

STUN помогает узнать внешний адрес, но не пересылает игровой трафик.
Некоторые сочетания симметричного NAT, CGNAT и ограничительных сетевых экранов
не позволяют установить прямое соединение. Без TURN гарантировать подключение
между любыми двумя сетями нельзя. При неудаче клиент завершает попытку и
показывает причину; автоматического платного реле нет.

Попробуйте другую сеть, проводное подключение или уже поддерживаемый LAN/VPN
путь. Не отключайте системную защиту целиком ради подключения.
Официальное описание ограничений STUN и роли TURN:
[WebRTC: TURN server](https://webrtc.org/getting-started/turn-server).

## 5. Локальная проверка разработчиком

Локальный Worker не требует входа в Cloudflare и публикации:

```powershell
cd online\signaling
npm.cmd ci
npm.cmd test
npm.cmd run dev
```

В отдельном PowerShell из корня репозитория:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\BuildOnlineDeps.ps1 -BuildTests
.\work\online-native\build-Win32\Release\NetOnlineTests.exe http://127.0.0.1:8787
```

Нативный тест создаёт четыре клиента без окон. Он проверяет версии, пароль,
полноту комнаты, состояние игры, кик, завершение потоков и реальный обмен через
ICE/DTLS/SCTP: максимальный кадр 65 538 байт и 32 упорядоченных сообщения.
Успешный результат — `ONLINE_TESTS passed=15 failed=0`; тест Worker — 8/8.
Это проверка транспорта на одном компьютере. Между двумя внешними сетями
нужен отдельный запуск после настройки настоящего URL.

## Частые ошибки

| Сообщение | Что проверить |
| --- | --- |
| `WebRTC runtime missing` | `datachannel.dll` рядом с EXE, правильная Win32/x64 архитектура, установлен подходящий Microsoft VC++ Runtime. |
| `Signaling connection failed` | Полный HTTPS-адрес Worker, доступность `/health`, успешная публикация и действительный TLS-сертификат. |
| `version-mismatch` | Все участники запустили EXE из одного готового архива. |
| `wrong-password` | Пароль комнаты; после ошибки выдержите предложенную задержку. |
| `room-full` | Лимит включает хоста и клиентов, ещё устанавливающих ICE-соединение. |
| Пустой список | Совпадают URL и сборка; хост оставил игру запущенной; обновите список. |
| `Direct connection failed` | Возможны ограничения NAT/сети; используйте другую сеть либо LAN/VPN. |
